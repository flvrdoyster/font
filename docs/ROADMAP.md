# 도깨비DNR 고딕 — 로드맵

파생 방향 확정 이후의 작업 계획. 3개 페이즈로 진행한다.

## 공통 설계 (전 페이즈 관통)

- 웨이트 2종, 둘 다 정적 폰트(픽셀 폰트는 보간이 무의미). **Light는 Regular에서 기계적으로 파생** — 별도 수작업이 아니다.
- 획 문법
  - **Regular**: 세로 줄기 2px / 가로 바·크로스바 1px / 대각선 1px 계단
  - **Light**: Regular에서 **세로 줄기만 1px로** 줄임 → 전 획이 균일 1px
- 수직 밴드
  - 한글: row 1–13 (13행, 상하 1px 여백)
  - 라틴: cap row 2 ~ baseline row 12 (11행), x-height row 6~, 디센더 row 13–15
- 제작 방식: [gensei-pc98](../../gensei-pc98) 저장소의 `docs/bios/font.bmp`(PC-98 BIOS 폰트, 16px 그리드)에 해당 글자가 있으면 그 골격을 참조해 위 문법으로 재작성. 원본에 아예 없는 글자(₩ 등)만 신규 드로잉.

## Phase 1 — Regular 웨이트 완성

- 범위: 영문 소문자 **반각 a–z + 전각 ａ–ｚ** (52자)
- 신규 설계 요소: 소문자에서 처음 쓰는 x-height·어센더·디센더
  - x-height 몸통: a, c, e, m, n, o, r, s, u, v, w, x, z
  - 어센더(cap 라인까지): b, d, f, h, k, l, t
  - 디센더(row 13–15 사용): g, j, p, q, y
- 순서: 반각을 먼저 만들어 손으로 다듬고, 전각은 PC-98 소문자 골격으로 같은 방식 파생 (대문자 작업 때와 동일 패턴)
- 완료 기준: 라틴·숫자 전 범위(대/소문자 × 반/전각) 완성 = 약물·가나를 제외한 Regular 웨이트 사실상 완성

## Phase 2 — Light 웨이트 → PC-98 BMP

- 범위: **전체 폰트** — 한글 11,172자 + 라틴/숫자 전부
- 방식: Regular의 세로 2px 줄기를 1px로 기계적으로 얇힘
  - 라틴/숫자: 커스텀 글리프에 적용 (상대적으로 쉬움)
  - 한글: 원본 도깨비 디나루 비트맵 11,172자에 일괄 적용 (핵심 작업)
- 리스크: 2px→1px 축소 시 획 접합부가 끊기거나 약해지는 글자가 발생할 수 있음. 안정적인 thinning 알고리즘(어느 열을 남길지, 교차점 처리)과 표본 QA가 필요하며 문제 글자는 수동 보정 가능성 있음
- 산출물: Light 웨이트 TTF + **gensei-pc98용 `font.bmp`** (해당 레포의 손그림 한글을 이 폰트로 대체). PC-98 원본이 1px 획 계열이라 무게가 맞음
- 완료 기준: Light 웨이트 + PC-98 BMP 납품

## Phase 3 — 약물/기호 + 가나 (장기)

- 산세리프 스타일로 재작성
  - 약물/기호: 원본에 있는 것은 PC-98/원본 골격 참조, 결손된 것(₩, —, •, © 등 `coverage_report.py` 목록 27자)은 신규 드로잉
  - 가나: 반각 가타카나 63자 완전 신규, 전각 히라가나/가타카나 168+자는 원본 필체형 → 한글 톤의 기하학적 스타일로 재설계
- 규모가 커 Regular/Light 골격이 끝난 뒤 별도 진행. 완료 시 두 웨이트 모두에 반영

## 검증 참고

- `scripts/verify_ttf.py`(픽셀-정확 회귀 테스트)는 **손대지 않은 한글에만** 유효하다. Phase 2에서 한글도 변형되므로 그 이후에는 이 테스트 대신 별도 시각 QA + fontbakery로 검증한다.
