# 도깨비DNR 고딕 — 로드맵

**목표**: 도깨비 디나루 16×16 비트맵을 Regular(1px 줄기)·Bold(2px 줄기) 한
패밀리로 재설계하고, Regular를 [gensei-pc98](../../gensei-pc98) PC-98
에뮬레이터의 실제 한글 폰트로 납품한다.

## 현재 상태

한글 11,172음절 + 호환 자모 93자, 라틴/숫자/핵심 기호가 두 웨이트에 완전히
동일한 cmap으로 들어 있다. gensei-pc98 납품 완료, 웹폰트(WOFF2) + GitHub
Pages 자동 배포 완료. 일본어(가나·한자)와 원본 비트맵의 상속 잡동사니(그리스·
키릴·원문자 등 669자)는 범위 밖으로 확정 제외했다.

| | |
|---|---|
| 한글 음절 | 11,172/11,172 |
| 호환 자모 (`ㄱㄴㄷ`·`ㅏㅑㅓ`, 옛한글 포함) | 93/93 |

## 설계

- **한 RIBBI 패밀리**: 1px 줄기 = Regular(기본), 2px 줄기 = Bold. 내부 코드의
  `weight` 키(`regular`=2px, `light`=1px)와 파일명(`glyphs_bold.json`=2px,
  `glyphs_light.json`=1px)은 여전히 **줄기 두께**를 뜻하며 패밀리 병합과
  무관하다. 컴파일된 OpenType 이름/OS2/fsSelection만 Regular/Bold
  (`tools/metadata.py`).
  - 라틴/숫자: 2px를 손으로 그리고 1px는 얇혀서 파생(`tools/thin_vertical.py`).
  - 한글: 2px는 원본 비트맵을 픽셀-정확 벡터화, 1px는 이를 얇힌 뒤 손으로 확정.
- **획 문법**: 2px는 세로 줄기 2px·가로 바 1px·대각선 1px 계단. 1px는 세로
  줄기만 1px.
- **수직 메트릭스**: 16행 셀에서 한글은 상하 1px씩 여백을 두고 13행을 쓴다.
  라틴은 베이스라인부터 캡하이트까지 11행 — 그 안에 엑스하이트·어센더·
  디센더가 들어간다.
- **범위**: 한글 음절(11,172) + 손그림(`glyphs_bold.json`/`glyphs_light.json`)
  만 싣는다(`build_ufo.py`의 `_in_scope()`). 원본 비트맵엔 이 서체 디자인이
  아닌 상속 글리프가 섞여 있어서(그리스·키릴·원문자·괄호 한글 등 669자 —
  글자마다 잉크 위치가 제각각이고 이 서체의 수직 메트릭스(13행/11행 규칙)를
  안 지킴) 명시적으로 제외한다. 가나·한자도 같은 이유로 상시 제외
  (`_KANA_RANGES`) — 반각 CJK 문장부호 `｡｢｣､`(U+FF61-64)는 가나가 아니라서
  예외.
- **에디터**(`tools/pixel_editor.html`): 상단 탭으로 Regular/Bold 분리, 저장
  파일도 웨이트별 독립. 빌드(`scripts/build_ufo.py --weight regular|light`)도
  동일하게 대응.

## 한글 11,172자 — 부품 조합 모델

확정 2,350자(KS X 1001, `glyphs_light.json`)는 손그림 그대로 verbatim 유지.
나머지 8,822자는 자모 부품 조합으로 채운다(`scripts/compose_components.py`).

- **벌식(context-dependent variants)이 필요하다** — 부품이 단순 가법적이지
  않음을 실측(48,063쌍 검정, 68%만 가법적). 초성+중성을 합친 `LV`셀
  798개(`(초성,중성,받침유무)`) + 종성 `T`셀 358개(`(종성,중성)`, 겹받침
  11종만 폭 기준 2벌) = 부품셀 1,156개.
- **추출은 PC-98 완성형 비트맵의 받침 변이 zone**으로 하고, KS X 1001 밖
  대표 음절(부품 셀 에디터에서 그림)은 이미 측정된 부품을 **뺄셈**으로
  분리한다. 알고리즘의 안전장치(`LV_FLOOR`, zone 누출 처리 등)는
  `compose_components.py`의 함수 docstring이 최신 기준 — 여기 중복 서술하지
  않는다.
- **추출 결과는 `tools/component_library.json`에 고정(freeze)**되어 있고,
  실제 폰트 빌드는 이 파일과 확정 코퍼스만 읽는다 — PC-98 비트맵 없이도
  빌드된다(자기 완결적). 재고정은 `compose_components.py --freeze`를 수동
  실행할 때만 일어난다(에디터 빌드 버튼은 자동으로 안 함 — 검수 통과한
  라이브러리를 조용히 갈아치우지 않기 위해).
- **품질 체(sieve)로 쓸 수 있는 건 3×3 꽉 찬 덩어리(벽돌) 하나뿐**이다 —
  확정 손그림엔 절대 안 나오는 형태라서. 샘플 불일치·평균 픽셀 오차는 1px
  광학 보정을 오답으로 세는 지표라 품질 판단에 못 쓴다(`--validate`/`--loo`
  숫자를 볼 때 항상 이 전제 위에서 읽을 것).
- 참조 데이터 원본은 `original/pc98_font.bmp` — gensei-pc98이 한때 자기
  자신(도깨비DNR)으로 교체됐던 오염본이 아니라 순정본(2026-07-31 확인·복구).

## 완성형 2,350자 확정 방식

대표 음절(초성 19×6블록 + 홑/겹받침, 총 166자)을 PC-98 둥근모꼴과 원본
도깨비 디나루를 겹쳐 보며 손으로 그리고, 자음을 **모임꼴**(모음 배치에 따른
분류 — 세로모임·가로모임·섞임모임, 받침 유무로 다시 갈림. 코드의
`vgroup()`/`cho_bt()`)별로 나머지 글자에 적용해 2,350자를 채운 뒤
(`compose_light.py`) 전량 검수·확정했다. 이 도구는 KS X 1001 밖을 못 다뤄
위 11,172자 확장엔 안 쓰인다.

## 반각 한글 (gensei-pc98 전용)

폰트 빌드와 별개. PC-98 ROM의 반각 한글 표(`font.bmp` col10-11, 유니코드
반각 자모 블록과 무관한 ROM 고유 배열)의 188칸 중 122칸(원본 잉크 있는 칸
전부)을 `tools/halfwidth_editor.html`로 손그림 완료
(`tools/glyphs_halfwidth.json`). `scripts/build_pc98_bmp.py`가 완성형 한글과
함께 `font_light.bmp`에 반영한다. `build_ufo.py`(TTF/OTF)는 이 데이터를
읽지 않는다.

## 검증

`scripts/verify_ttf.py`는 웨이트별로 "의도한 값"을 다르게 비교한다 — Bold는
원본 비트맵(`glyphs_bold.json` 손교정 우선), Regular는
`glyphs_light.json` 손그림 ∪ 부품 조합 결과. 둘 다 `_in_scope()`로 걸러진
글리프는 기대값에서도 제외해 가짜 불일치를 막는다. `--proportional` 빌드의
좌우 이동(`tools/spacing.py`)도 반영. 현재 둘 다 불일치 0건 — 시각 QA +
fontbakery는 별도로 병행한다.
